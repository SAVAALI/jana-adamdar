# Время и Стекло

Адаптивный интерактивный прототип сайта молодёжной команды Астаны. Яркая жёлто-фиолетово-белая палитра, крупная типографика и иллюстрация командного рейда. HTML5, Tailwind CSS через CDN, собственные стили и обычный JavaScript. Установка зависимостей и сборка не нужны.

## Запуск

Запустите локальный сервер и откройте страницу в современном браузере:

```bash
cd /workspace/jana-adamdar
python3 -m http.server 8000 --bind 0.0.0.0
```

Откройте адрес сервера на порту 8000 в своём браузере. Для локального запуска на компьютере это `http://localhost:8000`. В облачной среде используйте доступный механизм просмотра порта.

## Общая база Supabase

Код подключения общей базы, входа, фотографий и проверки отчётов подготовлен. Пошаговая настройка нового проекта описана в [`supabase/README.md`](supabase/README.md), готовый SQL — в [`supabase/setup.sql`](supabase/setup.sql).

Сейчас `config.js` содержит `enabled: false`: опубликованный сайт продолжает работать как прототип. После создания таблиц и настройки писем можно включить общую базу. Демонстрационные магазины не будут загружены в Supabase.

Приложение использует локальную официальную сборку Supabase JS 2.118.0. Архив npm проверен по SHA-512; источник и контрольная сумма записаны в `assets/supabase-provenance.json`.

## Публикация на GitHub Pages

Проект готов для статического размещения без установки зависимостей и сборки. Файл `.nojekyll` позволяет GitHub Pages отдавать HTML, JavaScript, CSS и локальные ресурсы напрямую.

После загрузки проекта в `SAVAALI/jana-adamdar`:

1. В репозитории откройте **Settings → Pages**.
2. В разделе **Build and deployment** выберите **Deploy from a branch**.
3. Укажите ветку **main**, папку **/ (root)** и нажмите **Save**.
4. Дождитесь успешной публикации в разделе **Actions** или **Pages**. Используйте адрес, который покажет GitHub после завершения.

При следующих обновлениях ветки `main` GitHub Pages обновляет сайт автоматически. Доступность Pages для приватных репозиториев зависит от тарифа GitHub. Настройка публикации не меняет видимость репозитория.

Публикация открывает доступ к прототипу. Данные отчётов по-прежнему сохраняются в браузере участника; общая база отчётов и серверная загрузка фотографий потребуют отдельного backend.

## Что работает

- Схематичная карта Астаны: выбор меток, масштабирование и переход в карточку.
- Фильтры «Все точки», «Есть нарушения», «Всё чисто» и поиск по названию или адресу.
- Подробная карточка: адрес, результат, дата и время в часовом поясе Астаны (UTC+5), описание, галерея и просмотр фото в увеличении. Закрытие по кнопке, вне окна или Escape.
- Новый отчёт для существующего или нового магазина, выбор результата проверки, загрузка фотографий с устройства и перетаскиванием, превью и удаление фото.
- Проверка формата, размера и содержимого изображений: JPG/PNG/WEBP, максимум 6 фото по 8 МБ. Минимум одна фотография и описание из 10 символов обязательны.
- После отправки новый магазин добавляется в список и на карту; для существующего обновляется последняя проверка. Предыдущие проверки сохраняются в локальных данных, интерфейс показывает последнюю.
- Отчёты и фото сохраняются в IndexedDB в текущем браузере и восстанавливаются после перезагрузки. Если сохранение недоступно, интерфейс явно предупреждает о временном хранении.
- Мобильное меню, адаптивная форма, управление клавиатурой, модальные окна с удержанием фокуса, учёт настройки уменьшения анимации.

## Границы прототипа

Все исходные магазины, результаты и общая статистика вымышлены. Фото в демо-карточках — иллюстрации, а не доказательства. Базовые показатели 128 / 36 / 24 демонстрационные; новые проверки увеличивают соответствующие счётчики. На карте показаны восемь последних демо-точек и добавленные пользователем магазины.

Карта не использует геокодирование: новые метки получают условное положение. В демо-режиме серверной отправки и синхронизации между устройствами нет. Общая база, вход и модерация включаются после настройки Supabase по инструкции выше. Не загружайте личные данные и фотографии чеков с чувствительной информацией.

Данные привязаны к источнику страницы (протокол, домен, порт). Для сохранения отчётов между запусками используйте один адрес. Очистка данных сайта в браузере удалит локальные отчёты. Приватный режим и ограничения хранилища могут препятствовать сохранению.

Tailwind 4.1.18 загружается через jsDelivr по HTTPS; при недоступности CDN автоматически используется локальная копия. Шрифты Golos Text и Playfair Display, фотографии и SVG-карта находятся локально в `assets/`. Демо-режим работает без интернета; для общих отчётов нужен доступ к Supabase.

Предоставленные ссылки-референсы не удалось загрузить в облачной среде (прокси вернул 403); оформление использует жёлтый, фиолетовый и белый по описанию пользователя. Иллюстративные фотографии созданы специально для прототипа с помощью генерации изображений. Локальные шрифты получены из официальных пакетов Fontsource через jsDelivr; лицензии OFL сохранены в `assets/fonts/`.

При обновлении оформления исходные демо-точки заменяются адресами Астаны; добавленные участниками записи и фотографии сохраняются без изменения.

## Проверки для разработчика

Node.js нужен только для проверок, статический сайт работает без него.

```bash
npm ci
npm run check
npm test
```

`npm test` запускает настоящий PostgreSQL через PGlite: проверяются повторный запуск схемы, RLS, разделение ролей, доступ к фото, публикация, защита от повышения прав и повторная отправка.

Для браузерной проверки запустите сайт обычной командой `python3 -m http.server 8000` в отдельном терминале, затем:

```bash
# Если Chromium ещё не установлен:
npx playwright install chromium
npm run test:browser
```

Тест использует официальный Supabase SDK и локальные HTTP-фикстуры: проверяет вход, регистрацию, отправку с повторной попыткой, кабинет, публикацию и адаптивность. Он не отправляет письма и не меняет ваш проект Supabase. Другой адрес сервера можно передать через `VSG_TEST_BASE_URL`.

## Файлы

- `index.html` — структура страницы и доступные диалоги.
- `styles.css` — оформление, состояния и адаптивные стили.
- `app.js` — демо-данные, карта, поиск, форма, галерея и локальное хранение.
- `config.js`, `backend.js`, `cloud-ui.js` — публичные параметры подключения, Supabase API и кабинет команды.
- `supabase/` — схема, политики доступа и инструкции для администратора.
- `tests/` — проверки SQL/RLS и клиентского сценария.
- `assets/` — карта и иллюстрации.
